# 用户使用说明

最后更新：2026-06-18

本文档面向员工、管理员、财务和部门负责人。涉及操作路径均以线上地址 `https://ai.seapllo.com` 为准。

## 1. 登录

1. 打开 `https://ai.seapllo.com`。
2. 点击 Enter 进入飞书授权。
3. 使用公司飞书账号授权。
4. 成功后进入 `/dashboard`。

登录失败常见原因：

- 飞书应用可用范围未包含该员工。
- 员工在系统里被标记为 `disabled`。
- 飞书回调地址未配置：`https://ai.seapllo.com/api/auth/feishu/callback`。
- 飞书应用凭证过期或配置错误。

## 2. 员工 API Key

页面：`/dashboard/key`

规则：

- 首次使用需要点击新建 Key。
- 新建成功后完整 Key 只显示一次。
- 后续页面只显示脱敏 Key，不能再次复制明文。
- 忘记 Key 时需要新建新的 Key。
- 可以删除 Key，但系统要求至少保留一个。
- 默认最多保留 5 个 Key；达到上限时需要先删除不用的 Key。
- 连续新建过快会被系统临时拦截，稍后再试即可。
- 员工 Key 必须以 `sk-emp-` 开头。
- 不要填写 DeepSeek、硅基流动等供应商官方 Key。

## 3. 客户端配置

普通 OpenAI 兼容客户端：

- Base URL：`https://ai.seapllo.com/v1`
- API Key：本页新建的 `sk-emp-...`
- 模型名：管理员在渠道和模型价格里配置的模型名，例如 `deepseek-v4-pro`

Claude Code：

- Base URL：`https://ai.seapllo.com/anthropic`
- API Key：本页新建的 `sk-emp-...`
- 模型名：使用系统里可用的 Claude 兼容模型名

## 4. 我的用量

页面：`/dashboard`

可查看：

- 今日调用次数。
- 今日 token 和费用。
- 本月已用额度。
- 本月额度百分比。
- 模型分布。
- 历史明细。

统计时间按北京时间计算。

## 6. 渠道管理操作规范

新增或修改渠道时：

- Base URL 填供应商 OpenAI 兼容根地址，不要填本系统域名。
- API Key 填供应商完整明文 Key。
- 如果页面显示脱敏值，不要复制脱敏值再次保存。
- 模型列表必须包含实际要调用的模型。
- 状态为 `disabled` 的渠道不会被代理调用，也不会触发余额告警。
- 优先级数字越小越优先。
- 同一模型可配置多个渠道，主渠道失败后 Proxy 尝试后续渠道。

## 7. 模型价格操作规范

模型可被调用必须同时满足：

- 至少有一个启用渠道支持该模型。
- `model_prices` 里有该渠道专属价格或全局价格。
- 价格未被删除或黑名单阻止同步。

价格字段含义：

- 输入价：每百万输入 token 价格。
- 输出价：每百万输出 token 价格。
- 缓存价：每百万缓存命中输入 token 价格。
- 币种：`CNY` 或 `USD`。USD 价格会按汇率换算成人民币计费。

手动编辑价格后，`synced_at` 会清空，后续官方同步不会覆盖该价格。

## 8. 限额设置

限额按月统计，北京时间自然月。

优先级：

1. 个人额度。
2. 部门额度。
3. 公司额度。

任一层额度用完，API 调用会返回 429。

注意：

- 额度为 `0` 表示硬阻断。
- 批量修改个人额度后，应抽查用户本月额度百分比。
- 如果未到 100% 却 429，可能是请求预占额度导致，管理员应检查 `quota_reservations`。

## 9. 预警和通知

预警类型：

- 个人额度阈值。
- 个人额度 100%。
- 部门额度阈值。
- 公司额度阈值。
- 异常用量。
- 渠道余额不足。
- 员工离职停用。
- 排行榜。

个人额度提醒直接发给员工本人。

管理类提醒按后台接收人配置发送；如果未配置接收人，默认发给全部活跃管理员。

余额提醒默认北京时间：

- 09:30
- 12:00
- 14:30
- 17:30

余额自动同步默认每小时一次，不一定每次都发提醒。

## 10. 财务角色

财务可查看：

- 全局概览。
- 部门分账。
- 自己的用量和 API Key。

财务不可操作：

- 渠道 Key。
- 模型价格。
- 权限。
- 限额。

## 11. 部门负责人角色

部门负责人可查看：

- 本部门排行。
- 本部门员工排行。
- 本部门分账。
- 自己的用量和 API Key。

部门负责人只能看本部门数据。

## 12. 客户端配置

员工使用 Sparkloom Key，不使用供应商官方 Key。

OpenAI 兼容客户端：

- Base URL：`https://ai.seapllo.com/v1`
- API Key：本页新建的 `sk-emp-...`
- Model：选择后台已开放的模型，例如 DeepSeek 或其他渠道模型

Claude Code：

- Base URL：`https://ai.seapllo.com/anthropic`
- API Key：本页新建的 `sk-emp-...`
- 不要填写 DeepSeek、SiliconFlow、OpenAI 或 Anthropic 官方 Key。

如果客户端提示 Key 无效，先确认复制的是新建时的一次性明文，不是带星号的脱敏值。

## 13. 提交问题时需要提供的信息

员工反馈问题时，请提供：

- 登录账号姓名。
- 问题发生时间。
- 使用的客户端。
- 模型名。
- 错误截图。
- 是否刚新建或删除过 Key。
- 如为 API 调用问题，提供 HTTP 状态码和错误文本，不要提供完整 API Key。

管理员排查时参考 `SUPPORT-RUNBOOK.md` 和 `TROUBLESHOOTING.md`。
