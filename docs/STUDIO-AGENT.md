# Sparkloom Studio and Local Agent

Sparkloom Studio is a browser workspace for Sparkloom gateway setup and local Agent SDK execution. It uses the existing Sparkloom employee key model and does not require Anthropic OAuth.

## User Flow

1. User logs in to Sparkloom.
2. User opens `/studio`.
3. User downloads and installs Sparkloom Agent from `/download`.
4. Studio detects the local Agent at `http://127.0.0.1:39271/health`.
5. User creates a Studio key. The raw `sk-emp-*` value is shown once.
6. User selects an Anthropic-compatible Sparkloom model alias such as `claude-sparkloom-deepseek-v4-flash`.
7. Agent writes the local Sparkloom gateway env file after local confirmation.
8. User sends tasks from Studio. The browser calls local Agent `/ws`, and the Agent runs the task through `@anthropic-ai/claude-agent-sdk` against `https://ai.seapllo.com/anthropic`.

## Local Development Preview

Production login still uses Feishu OAuth. Local preview can use the development login only when all of these are true:

- `NODE_ENV` is not `production`.
- `ENABLE_DEV_LOGIN=true`.
- The request host is `localhost`, `127.0.0.1`, or `[::1]`.

Recommended local preview command:

```powershell
$env:ALLOW_INSECURE_DEV_AUTH="true"
$env:ALLOW_PLAINTEXT_SECRETS_FOR_DEV="true"
$env:ENABLE_DEV_LOGIN="true"
$env:AUTO_SYNC_ENABLED="false"
$env:AUTO_SYNC_ON_STARTUP="false"
$env:DATABASE_URL="F:\文档\词元管理系统\web\data.db"
pnpm --filter web exec next dev --port 3014 --hostname 127.0.0.1 --turbopack
```

Open `http://localhost:3014/studio`. Use `localhost` rather than `127.0.0.1` during browser testing so the login cookie and redirect host stay aligned.

If the local `users` table is empty, `dev-login` creates one local-only admin user so Studio can be previewed. This does not import production Feishu personnel. To preview with real Feishu-synced users, restore or sync the intended database before opening Studio.

## Sparkloom Gateway Variables

```env
ANTHROPIC_BASE_URL=https://ai.seapllo.com/anthropic
ANTHROPIC_AUTH_TOKEN=sk-emp-...
CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1
ANTHROPIC_MODEL=claude-sparkloom-<model>
```

`ANTHROPIC_AUTH_TOKEN` must be the employee key generated by Sparkloom. Do not use DeepSeek, SiliconFlow, OpenAI, or Anthropic provider keys here.

## Model Aliases

Sparkloom gateway discovery uses Anthropic-shaped model ids. Sparkloom exposes non-Claude upstream models with a safe alias:

- Real model: `deepseek-v4-flash`
- Sparkloom model id: `claude-sparkloom-deepseek-v4-flash`

The proxy maps `claude-sparkloom-*` back to the real model before upstream routing. Billing and usage are recorded against the real model.

## Local Agent

The Agent is a Node.js local service in `agent/` with one runtime dependency:
`@anthropic-ai/claude-agent-sdk`.

Windows release zip files keep the top level simple for non-technical users:

- `Start Sparkloom.cmd`: one-click install/start/open flow.
- `README.txt`: Chinese quick-start instructions.
- `support/`: internal scripts, bundled skills, and the no-dependency Node Agent.

Users must extract the zip before running these files. Running from the
compressed-folder preview can break relative file paths.

The Windows launcher copies Agent files into `%LOCALAPPDATA%\SparkloomAgent\app`,
creates a `Sparkloom Studio` desktop shortcut, starts the local Agent in the
background, and opens Studio with a local pairing token in the URL fragment.
Studio stores that token in browser local storage, removes it from the address
bar, and sends it as `x-sparkloom-agent-token` to local Agent APIs. The token is
never sent to the Sparkloom server.

Supported endpoints:

- `GET /health`
- `GET /environment`
- `GET /claude/status`
- `POST /claude/configure`
- `GET /ws`
- `GET /skills/status`
- `POST /skills/install`

The Agent binds only to `127.0.0.1`. Allowed browser origins default to production plus common local preview ports. Extra origins can be appended with `SPARKLOOM_ALLOWED_ORIGINS`, using comma-separated absolute origins.

Configuration and skill installation endpoints require a local confirmation header:

```http
x-sparkloom-local-confirm: configure-claude-code
x-sparkloom-local-confirm: install-reviewed-skills
x-sparkloom-agent-token: <local pairing token>
```

`GET /ws` is the only Studio task execution transport. The browser connects
with the local pairing token in the query string and sends a `run` message. The
Agent executes through `@anthropic-ai/claude-agent-sdk`, streams `status`,
`tool`, `delta`, `result`, and `done` events, and accepts a `cancel` message for
the active request. `POST /claude/run` is retired and returns `410`.

Studio sends one of these modes:

- `default`: Ask mode. The SDK uses its default permission flow and asks before restricted tool use.
- `plan`: Plan mode. The task is intended for analysis and planning before file changes.
- `auto`: Auto mode. The SDK may proceed automatically, still constrained by local Agent boundaries and the current OS user.

`GET /claude/status` returns whether the local gateway env file exists, the configured base URL, selected model, model discovery flag, and SHA-256 token hash. It must never return the raw `sk-emp-*` token.

`GET /skills/status` compares bundled Sparkloom skills with `~/.claude/skills/` and returns installed/missing names.

The Agent writes Sparkloom gateway env content to:

```text
~/.sparkloom/claude-code.env
```

It installs reviewed Sparkloom skills to:

```text
~/.claude/skills/
```

For automated tests, enterprise packaging, or lab validation, these directories can be overridden without touching the real user profile:

```env
SPARKLOOM_CONFIG_HOME=/tmp/sparkloom-config
SPARKLOOM_SKILLS_HOME=/tmp/sparkloom-skills
```

Production installers should normally leave these unset so configuration follows the current OS user profile.

## Studio Workspace APIs

Studio persists chat state and execution mode through these authenticated web APIs:

- `GET /api/studio/sessions`
- `POST /api/studio/sessions`
- `GET /api/studio/sessions/:sessionId`
- `PATCH /api/studio/sessions/:sessionId`
- `POST /api/studio/sessions/:sessionId/messages`

Legacy command record APIs still exist for compatibility with old data, but the current Studio UI does not expose command cards. Actual task execution goes through local Agent `/ws`.

## Built-in Skills

The bundled skills are company-owned prompts only. They do not contain secrets and do not auto-run dangerous commands.

- Project startup check
- Code review
- Bug fix
- Frontend UX review
- Next.js check
- Dependency repair
- Release check
- Git summary

## Safety Rules

- Web pages must not directly run installers.
- Agent must not store or read provider keys.
- Agent must not log raw `sk-emp-*` values.
- Agent must not run as administrator/root/System.
- Ask mode should remain the default for general users.
- Plan mode is preferred when users only want a proposal before changes.
- Auto mode should be limited to trusted users or trusted projects until a separate security review approves broader rollout.

## Release Variables

Generate release zip files before publishing `/download`:

```bash
pnpm agent:package
```

The command writes platform zip files and a `manifest.json` to:

```text
handoff-packages/studio-agent-build/
web/public/downloads/studio-agent/
```

Docker builds run `pnpm agent:package` before `next build`, so Railway can serve the bundled zip files directly from the Sparkloom domain:

```text
/downloads/studio-agent/sparkloom-agent-0.4.0-windows.zip
/downloads/studio-agent/sparkloom-agent-0.4.0-macos.zip
```

Keep `STUDIO_AGENT_RELEASE_REQUIRED=true` in production. When no external URLs are configured, `railway/start.mjs` validates the bundled manifest, zip existence, and SHA-256 hashes before serving traffic.

If you prefer a CDN/object-storage host, upload the zip files to that host, then copy the SHA-256 values from `manifest.json` into the production environment:

```env
PUBLIC_APP_URL=https://ai.seapllo.com
STUDIO_AGENT_RELEASE_REQUIRED=true
STUDIO_AGENT_VERSION=0.4.0
STUDIO_AGENT_WINDOWS_URL=https://.../sparkloom-agent-0.4.0-windows.zip
STUDIO_AGENT_WINDOWS_SHA256=<sha256 from manifest>
STUDIO_AGENT_MAC_URL=https://.../sparkloom-agent-0.4.0-macos.zip
STUDIO_AGENT_MAC_SHA256=<sha256 from manifest>
```

Unsigned local preview builds must not be marketed as production-ready installers. For broad rollout, sign and notarize macOS artifacts and code-sign Windows artifacts before setting public download URLs.
